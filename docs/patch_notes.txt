📢 [PATCH NOTES] อัปเดต v2.10.0: ยกระดับ Quant Engine — ยืดหยุ่นตามสภาวะตลาด 4 ระดับ, สูตรแม่นยำขึ้น & กันความเสี่ยงงบการเงิน 🧠
======================================================================

🎯 1. ยืดหยุ่นตามเหตุการณ์ตลาด (4-Tier Adaptive Macro & Crisis Sizing)
----------------------------------------------------------------------
• แยกสภาวะตลาดเป็น 4 ระดับ (`classify_macro_regime`): เพิ่มระดับ **Crisis / High Volatility** (`VIX >= 35` หรือ SPX หลุด EMA50 > 5% พร้อม VIX >= 28) ดัน Hurdle เป็น 91 (สูงสุด 94 เมื่อดอกเบี้ยตึงตัว) และลด Macro Score เหลือ 4
• ใช้ข้อมูล `^TNX` (10Y Yield) และ `^NDX` (Nasdaq 100) จริง: หากดอกเบี้ยพันธบัตร >= 4.5% / >= 5.0% จะหักคะแนน Macro และเพิ่ม Hurdle อัตโนมัติ และหาก SPX ยืนเหนือ EMA50 แต่ NDX หลุด (Breadth Divergence) จะลดคะแนนเตือนความเสี่ยง
• Crisis Position Sizing: ลด Risk Budget ต่อไม้เหลือ **0.75%** ในช่วงตลาดวิกฤต (จากเดิม 1% Risk-Off / 1.5% Neutral / 2% Bull)

🧮 2. ปรับความแม่นยำของสูตรและอุดช่องโหว่ลอจิก
----------------------------------------------------------------------
• แก้บั๊ก `stop_loss` และขยายระยะหายใจ (`compute_entry_zone()`): ขยาย Stop Loss เป็น `2.2x ATR` (Target `3.5x ATR`, เพดานลึกสุด -15%) และบังคับให้ Stop Loss อยู่ต่ำกว่าราคาปัจจุบันเสมอ ลดการโดนสะบัดหลุด Stop ฟรีและกันค่า R:R เพี้ยน
• ผ่อนผัน Override สำหรับหุ้นผู้นำตลาดขาขึ้น: หุ้นที่เป็น **Stage 2 + RS Leader** ผ่อนผันเกณฑ์ถึง `RSI < 75` และ `ema_dist <= 10%` (หุ้นทั่วไปคงเกณฑ์เข้ม `RSI < 70` / `8%`)
• ปรับเกณฑ์ Hurdle จากผล Walk-Forward Calibration: `Bull 82 / Neutral 85 / Risk-Off 89 / Crisis 91` (ลด Max Drawdown ช่วง Out-of-Sample ลงเกือบครึ่ง)
• เพิ่มสคริปต์ Offline Backtester (`scripts/backtest.py`): ทดสอบสูตรย้อนหลัง 5 ปีพร้อม Walk-Forward Split และแคชข้อมูลในเครื่อง (0 ms impact ต่อบอท Discord)
• ลงโทษหุ้นงบแย่/เผาเงินสดจริงจัง: ลด Base Score และหักคะแนนเมื่อ `revenueGrowth < 0`, `earningsGrowth < 0`, `profitMargins < 0`, `forwardPE < 0`, หรือ `freeCashflow < 0` รวมถึงจำกัดเพดานคะแนนเมื่อข้อมูลพื้นฐานหาย และตรวจทาน `forwardPE` ควบคู่กับ `PEG`
• ปรับ Scale คะแนน Technical ไม่ให้ล้นเพดาน 20 ง่ายเกินไป: จำกัดโบนัสสัญญาณ Pro รวมไม่เกิน +5 คะแนน (ยังคง Penalty ฝั่งลบเต็มจำนวน) เพื่อแยกอันดับหุ้นเทพกับหุ้นกลางๆ ได้ชัดขึ้น
• รวมสูตร Fundamental/Valuation/Risk เป็นชุดเดียว (Single Source of Truth): `discord_bot.py` เรียกใช้ฟังก์ชันเดียวกับ `scan_stocks.py` โดยตรง คะแนนตรงกัน 100% ไม่มี Model Drift

📅 3. กันความเสี่ยงก่อนประกาศงบ (Earnings Blackout Guard)
----------------------------------------------------------------------
• ตรวจวันประกาศงบจากข้อมูล `info` อัตโนมัติ (ไม่ยิง API เพิ่ม): หากหุ้นรายตัวใกล้ประกาศงบใน **<= 5 วัน** จะลดสถานะ `BUY ➔ HOLD` เพื่อเลี่ยงความเสี่ยง Gap ข้ามคืน และแสดงป้ายเตือนใน `/check` เมื่อใกล้ประกาศงบใน <= 7 วัน

✅ 4. ผลการทดสอบ & Backtest (Verification)
----------------------------------------------------------------------
• แก้บั๊ก `--phase=trading` ใน `determine_scan_phase()` ให้รับค่าได้ถูกต้อง
• ผ่าน Unit Tests ครบ 29/29 เคส (`tests/test_bot_enhancements.py`) ครอบคลุมทุกสภาวะตลาด (Bull / High-Rate / Divergence / Crisis), บั๊ก Stop Loss, หุ้นเผาเงินสด, ความตรงกันของสูตร และ Earnings Guard
• ผล Offline Backtest 5 ปี (`scripts/backtest.py`, 16 หุ้น, Slippage 0.1%, Zero Look-Ahead):
  - In-Sample (2022–2025): Win Rate `66.4%`, Avg `+0.93%/ไม้`, Profit Factor `1.78`, MaxDD `-2.80%`, โดน SL ลดจาก `47.6%` → `15.0%`
  - Out-of-Sample (2025–2026): Win Rate `54.4%`, Avg `+0.18%/ไม้`, Profit Factor `1.13` (พลิกจาก `0.52`), MaxDD `-5.24%` (ลดจาก `-10.01%`), โดน SL ลดจาก `60.7%` → `16.2%`

🛡️ 2. Feedback, Error Handling & Logging
----------------------------------------------------------------------
• Global Error Handlers (`discord_bot.py`): เพิ่ม `@bot.tree.error` และ `on_command_error` ตอบกลับข้อความภาษาไทยชัดเจนเมื่อพิมพ์คำสั่งไม่ครบหรือเกิดข้อผิดพลาด โดยไม่เปิดเผย raw exception/stacktrace ให้ผู้ใช้
• แยกสาเหตุ Error ใน `PortfolioAddModal`: แจ้งแยกชัดเจนระหว่างพิมพ์ราคาไม่ถูกต้อง, ดึงราคาตลาดไม่ได้ หรือรูปแบบยอดซื้อผิด
• Rotating File Log (`logs/bot.log`): เมื่อรันบอทเบื้องหลังผ่าน `pythonw.exe` จะบันทึกลงไฟล์ `logs/bot.log` (หมุนไฟล์อัตโนมัติ 1 MB x 2) แทนการทิ้งลง `os.devnull` และแสดง error ใน `scan_stocks.py` เมื่อส่ง Toast/Discord ไม่สำเร็จ

⚙️ 3. สคริปต์, การตั้งค่า & เอกสาร
----------------------------------------------------------------------
• `scripts/start_bot.bat`: ปิดโปรเซสบอทตัวเก่าก่อนเปิดใหม่ ป้องกันบอทซ้อนตอบเบิ้ล

📢 [PATCH NOTES] อัปเดต v2.9.1: อุดช่องโหว่ความปลอดภัย & แก้บั๊กเสถียรภาพระบบ 🛡️
======================================================================

🔒 1. อุดช่องโหว่ความปลอดภัย (Security Hardening)
----------------------------------------------------------------------
• Supabase RLS (`scripts/setup_supabase.sql`): ถอด Policy `USING (true)` ที่เปิดกว้างออก จำกัดสิทธิ์ให้ใช้เฉพาะ `service_role` ฝั่งบอท (และ `auth.uid() = user_id` สำหรับผู้ใช้ที่ล็อกอิน)
• Guild & Admin Check (`discord_bot.py`): เพิ่ม `_tree_interaction_check` ให้ Slash Commands ตรวจ `DISCORD_GUILD_ID` เช่นเดียวกับ Prefix และจำกัดสิทธิ์คำสั่ง `/restart`, `!restart`, `!sync` เฉพาะเจ้าของบอทหรือ Admin ของกิลด์ที่อนุญาตเท่านั้น
• Input & Injection Validation: กรองชื่อหุ้นใน `clean_ticker` ด้วย Allowlist Regex ป้องกัน mention/markdown/path injection, ป้องกันค่า `NaN`/`Inf` ทำข้อมูล JSON/Supabase พัง และทำความสะอาดค่า `category`
• Hardcoded Owner ID (`scan_stocks.py`): ลบ Discord User ID ที่ฝังตายตัวออกจาก fallback ของ `save_refreshed_portfolio`
• Webhook SSRF & HTTPS Validation (`discord_notifier.py`, `discord_bot.py`): บังคับตรวจสอบ URL ของ Discord Webhook (`https://discord.com/api/webhooks/...`) และ Supabase (`https://`) รวมถึงซ่อน raw exception จากผู้ใช้ใน Discord
• Alert Privacy: ยกเลิกการส่ง fallback ของ Price Alert ไปยังช่องแชตสาธารณะแรกของเซิร์ฟเวอร์เมื่อส่ง DM ไม่สำเร็จ

🛠️ 2. แก้บั๊ก & เพิ่มเสถียรภาพ (Bug Fixes & Stability)
----------------------------------------------------------------------
• Race Condition & File I/O: ใช้ `_file_lock` (`RLock`) ครอบการอ่าน-แก้-เขียน Watchlist, Portfolio, Alerts และใช้ `tempfile.NamedTemporaryFile` แทน `.tmp` ชื่อตายตัว ป้องกันข้อมูลทับกันหรือไฟล์ชนกันระหว่างโปรเซส
• Watchlist & Portfolio Caps: บังคับเพดาน Watchlist (50 ตัว) บนปุ่มลัดหน้า `/check` และ `/price` และจำกัดพอร์ตไม่เกิน 50 ตัวต่อผู้ใช้ รวมถึงเช็คสิทธิ์ในปุ่ม `ScanView` และ Modals
• Price & History Embeds: กัน `ZeroDivisionError` เมื่อราคาปิดเป็น 0, กรองแถว `NaN` ท้ายตาราง และไม่แนบปุ่ม UI เมื่อชื่อหุ้นไม่ถูกต้อง
• HTTP Resource Leak & Graceful Restart: ปิด `HTTPError` หลังใช้งาน, เพิ่ม Header ความปลอดภัยให้ Health Check Server และสั่งซิงค์ Supabase ก่อนปิดโปรเซสตอนรีสตาร์ต

✅ 3. ผลการทดสอบ (Verification)
----------------------------------------------------------------------
• ผ่าน Unit Tests ครบ 27/27 เคส (`tests/test_bot_enhancements.py`) รวมเทสความปลอดภัยและ edge cases ที่เพิ่มใหม่
